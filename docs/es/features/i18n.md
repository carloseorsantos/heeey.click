# Internacionalización (i18n)

**Heeey** está construido con una arquitectura de internacionalización nativa y fuertemente tipada, con soporte completo para varios idiomas en la interfaz de la aplicación, en el editor Excalidraw, en las páginas del sitio y en esta documentación.

---

## 🌍 Idiomas disponibles

| Idioma | Código (`Locale`) | Código de Excalidraw (`excalidrawLangCode`) | Estado |
|---|---|---|---|
| **Português (Brasil)** | `pt-BR` | `pt-BR` | Idioma principal y de referencia |
| **English (US)** | `en-US` | `en` | Totalmente traducido |
| **Español (España)** | `es-ES` | `es-ES` | Totalmente traducido |

---

## 🧠 Arquitectura del sistema (`src/i18n/`)

La capa de i18n de Heeey está hecha a medida para ser muy ligera y reactiva, sin dependencias externas pesadas:

```
src/i18n/
├── index.tsx          # Provider de React, hook useI18n, detector y formateador ICU
└── locales/
    ├── pt-BR.ts       # Diccionario de mensajes en portugués (base de los tipos)
    ├── en-US.ts       # Diccionario de mensajes en inglés
    └── es-ES.ts       # Diccionario de mensajes en español
```

### 1. Tipado estricto en tiempo de compilación
- TypeScript extrae de forma recursiva todas las claves anidadas del diccionario `ptBR` y genera el tipo unión `MessageKey` (p. ej. `'dashboard.newBoard'`, `'sync.saving'`, `'auth.invalidEmail'`).
- Si algún componente usa una clave que no existe o tiene una errata, la compilación falla de inmediato.
- `en-US.ts` y `es-ES.ts` implementan la interfaz `Messages`, así que no puede faltar ninguna traducción.

### 2. Plurales al estilo ICU
Los mensajes dinámicos admiten reglas de plural complejas mediante el formateador `formatMessage`, que usa la API nativa `Intl.PluralRules`:

```typescript
// Ejemplo de es-ES.ts:
elements: '{count, plural, =0 {sin elementos} one {# elemento} other {# elementos}}',
othersOnline: '{count, plural, =0 {nadie más en línea} one {# persona más en línea} other {# personas más en línea}}',
```

### 3. Interpolación de parámetros
Sustitución sencilla de variables entre llaves:
```typescript
t('dashboard.movedToTrash', { title: 'Plan' });
// "“Plan” foi para a lixeira", "“Plan” moved to the trash" o "«Plan» movida a la papelera"
```

## 🔄 Detección y persistencia del idioma

Heeey elige el idioma del usuario en cuatro pasos:

1. **Parámetro `?lang=` en la URL**:
   - Los enlaces de las páginas del sitio (por ejemplo `/en` o `/es`) abren la app con `?lang=en-US` o `?lang=es-ES`, para que la app siga en el idioma de la página. La elección se guarda y el parámetro se quita de la barra de direcciones.
2. **Preferencia guardada (`localStorage`)**:
   - Si el usuario ya eligió un idioma en **Ajustes → Apariencia → Idioma**, se lee la clave `heeey_locale` del navegador.
3. **Detección del navegador (`navigator.languages`)**:
   - En la primera visita se revisa la lista ordenada de idiomas preferidos del navegador: `pt*` recibe `pt-BR`, `en*` recibe `en-US` y `es*` recibe `es-ES`.
4. **Valor por defecto**:
   - Para cualquier otro idioma, se usa `pt-BR`.

## 🌐 Páginas del sitio y documentación

Las páginas estáticas son archivos HTML independientes para cada idioma, para que los buscadores indexen el contenido completo de cada versión:

| Página | pt-BR | en-US | es-ES |
|---|---|---|---|
| Página de inicio | `/` | `/en` | `/es` |
| Servidor MCP | `/pt-br/mcp` | `/mcp` | `/es/mcp` |
| Términos de uso | `/termos` | `/en/terms` | `/es/terminos` |
| Privacidad | `/privacidade` | `/en/privacy` | `/es/privacidad` |

- Cada página declara sus versiones alternativas con `<link rel="alternate" hreflang="...">` y tiene un selector de idioma en el pie.
- Quien ya eligió un idioma (clave `heeey_locale`) va automáticamente a la versión correspondiente. Los buscadores no tienen esa preferencia y siempre reciben la página solicitada.
- La documentación sigue el idioma de la app: los archivos originales están en `docs/`, y las traducciones en `docs/en/` y `docs/es/`, con la misma estructura.

---

## 🎨 Sincronización con el lienzo de Excalidraw

El motor de Excalidraw incluye sus propias traducciones (herramientas, diálogos de exportación, paleta de colores y atajos).

Heeey pasa el idioma seleccionado directamente a la propiedad `langCode` del componente Excalidraw mediante `excalidrawLangCode`:
- Cuando el usuario cambia el idioma en Heeey, los botones, menús contextuales y diálogos del lienzo cambian de idioma al instante y la experiencia se mantiene uniforme.

---

## 📅 Formato de fechas y números

Todas las fechas de las tarjetas de pizarras y del historial de versiones se adaptan al idioma activo:
- En `pt-BR`: `"editado há 5 minutos"`, `"23 de setembro de 2026"`.
- En `en-US`: `"edited 5 minutes ago"`, `"September 23, 2026"`.
- En `es-ES`: `"editada hace 5 minutos"`, `"23 de septiembre de 2026"`.

## 🛠️ Cómo añadir un idioma nuevo

Para añadir un idioma nuevo (por ejemplo francés, `fr-FR`):

1. Crea `src/i18n/locales/fr-FR.ts` implementando la interfaz `Messages`.
2. Añade `'fr-FR'` al tipo `Locale`, una entrada al array `LOCALES` y el diccionario al mapa `DICTIONARIES` en `src/i18n/index.tsx`:
   ```typescript
   { id: 'fr-FR', label: 'Français', excalidrawLangCode: 'fr-FR' },
   ```
3. Enseña a `toLocale` a reconocer `fr*` y añade las URL de las páginas estáticas en `STATIC_PAGES`.
4. Traduce las páginas HTML estáticas y la documentación (`docs/fr/`, títulos en `DOC_TRANSLATIONS`).
5. Las pruebas automáticas de `src/__tests__/i18n.test.ts` y `src/__tests__/docs.test.ts` comprueban que estén todos los mensajes y todos los documentos traducidos.

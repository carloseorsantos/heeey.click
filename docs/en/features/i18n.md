# Internationalization (i18n)

**Heeey** is built with native, strongly typed internationalization, with full multi-language support in the app interface, in the Excalidraw editor, on the website pages and in this documentation.

---

## 🌍 Supported Languages

| Language | Code (`Locale`) | Excalidraw code (`excalidrawLangCode`) | Status |
|---|---|---|---|
| **Português (Brasil)** | `pt-BR` | `pt-BR` | Primary and reference language |
| **English (US)** | `en-US` | `en` | Fully translated |
| **Español (España)** | `es-ES` | `es-ES` | Fully translated |

---

## 🧠 System Architecture (`src/i18n/`)

Heeey's i18n layer is custom-built to be extremely light and reactive, with no heavy external dependencies:

```
src/i18n/
├── index.tsx          # React provider, useI18n hook, detector and ICU formatter
└── locales/
    ├── pt-BR.ts       # Portuguese message dictionary (source of the types)
    ├── en-US.ts       # English message dictionary
    └── es-ES.ts       # Spanish message dictionary
```

### 1. Strict Compile-Time Typing
- TypeScript recursively extracts every nested key of the `ptBR` dictionary into the `MessageKey` union type (e.g. `'dashboard.newBoard'`, `'sync.saving'`, `'auth.invalidEmail'`).
- If any component uses a key that doesn't exist or has a typo, the build fails right away.
- `en-US.ts` and `es-ES.ts` implement the `Messages` interface, so no translation can go missing.

### 2. ICU-Style Plurals
Dynamic messages support complex plural rules through the `formatMessage` formatter, which uses the native `Intl.PluralRules` API:

```typescript
// Example from en-US.ts:
elements: '{count, plural, =0 {no elements} one {# element} other {# elements}}',
othersOnline: '{count, plural, =0 {no one else online} one {# other person online} other {# other people online}}',
```

### 3. Parameter Interpolation
Simple substitution of variables wrapped in braces:
```typescript
t('dashboard.movedToTrash', { title: 'Plan' });
// "“Plan” foi para a lixeira", "“Plan” moved to the trash" or "«Plan» movida a la papelera"
```

## 🔄 Detecting and Remembering the Language

Heeey picks the user's language in four steps:

1. **`?lang=` URL parameter**:
   - Links on the website pages (for example `/en` or `/es`) open the app with `?lang=en-US` or `?lang=es-ES`, so the app stays in the page's language. The choice is saved and the parameter is removed from the address bar.
2. **Saved preference (`localStorage`)**:
   - If the user has picked a language under **Settings → Appearance → Language**, the `heeey_locale` key is read from the browser.
3. **Browser detection (`navigator.languages`)**:
   - On the first visit, the ordered list of the browser's preferred languages is checked: `pt*` gets `pt-BR`, `en*` gets `en-US` and `es*` gets `es-ES`.
4. **Default fallback**:
   - Any other language falls back to `pt-BR`.

## 🌐 Website Pages and Documentation

The static pages are separate HTML files per language, so search engines index the full content of each version:

| Page | pt-BR | en-US | es-ES |
|---|---|---|---|
| Home page | `/` | `/en` | `/es` |
| MCP server | `/pt-br/mcp` | `/mcp` | `/es/mcp` |
| Terms of use | `/termos` | `/en/terms` | `/es/terminos` |
| Privacy | `/privacidade` | `/en/privacy` | `/es/privacidad` |

- Every page lists its alternate versions with `<link rel="alternate" hreflang="...">` and has a language switcher in the footer.
- Visitors who already chose a language (the `heeey_locale` key) are taken to the matching version automatically. Search engines have no such preference and always get the page they asked for.
- The documentation follows the app's language: the original files live in `docs/`, and the translations in `docs/en/` and `docs/es/`, with the same structure.

## 🎨 Syncing with the Excalidraw Canvas

The Excalidraw engine ships its own translations (tools, export dialogs, color palette and shortcuts).

Heeey passes the selected language straight to the Excalidraw component's `langCode` prop through `excalidrawLangCode`:
- When the user changes the language in Heeey, the canvas buttons, context menus and dialogs switch language instantly, keeping the experience consistent.

## 📅 Date and Number Formatting

Every date shown on board cards and in the version history adapts to the active language:
- In `pt-BR`: `"editado há 5 minutos"`, `"23 de setembro de 2026"`.
- In `en-US`: `"edited 5 minutes ago"`, `"September 23, 2026"`.
- In `es-ES`: `"editada hace 5 minutos"`, `"23 de septiembre de 2026"`.

## 🛠️ Adding a New Language

To add support for a new language (for example French, `fr-FR`):

1. Create `src/i18n/locales/fr-FR.ts` implementing the `Messages` interface.
2. Add `'fr-FR'` to the `Locale` type, an entry to the `LOCALES` array and the dictionary to the `DICTIONARIES` map in `src/i18n/index.tsx`:
   ```typescript
   { id: 'fr-FR', label: 'Français', excalidrawLangCode: 'fr-FR' },
   ```
3. Teach `toLocale` to recognize `fr*` and add the static page URLs to `STATIC_PAGES`.
4. Translate the static HTML pages and the documentation (`docs/fr/`, titles in `DOC_TRANSLATIONS`).
5. The automated tests in `src/__tests__/i18n.test.ts` and `src/__tests__/docs.test.ts` check that every message and every translated document is in place.
